# Design Specification: Hermes-Inspired Skill Management for Shark Dev

- **Date**: 2026-09-16
- **Status**: Approved
- **Author**: Shark Dev Core Team & Antigravity
- **Reference**: `docs/hermes-skill.md`

---

## 1. Context & Motivation

Today, Shark Dev manages procedural knowledge (skills) through a basic implementation in `SkillManager`:
1. It injects `<skills_index>` with full descriptions into the initial system prompt.
2. When the agent selects a skill via `activate_skill`, the entire markdown body of `SKILL.md` is appended into the system prompt inside `<EXTREMELY_IMPORTANT>`.
3. **Problem**: Mutating the system prompt between turns invalidates the **Prompt Caching** mechanisms used by LLM providers (StackSpot, OpenAI, Anthropic, Gemini). This results in increased token latency and processing cost.
4. Furthermore, Shark Dev lacks support for:
   - Dynamic template variables (e.g. `${SHARK_SKILL_DIR}`).
   - Reading secondary skill assets (reference documents, auxiliary scripts in `references/` or `scripts/`).
   - Autonomous procedural learning (`skill_manage` for creating, patching, or archiving skills).
   - Governance gates (pinned skills protection, staged write approval, and safe archiving).

By adopting the architecture of **Hermes Agent** (`docs/hermes-skill.md`), Shark Dev gains:
- **Progressive Disclosure**: Only compact 1-line metadata in the initial index; full procedures are loaded strictly on-demand.
- **Cache Preservation**: Skill content enters the conversation history as an action/tool observation turn, keeping the base system prompt 100% frozen.
- **Procedural Autonomy & Learning**: Agent can create (`create`), modify (`patch`/`edit`), and manage auxiliary files (`write_file`/`remove_file`).
- **Enterprise Governance**: Protected pinned skills, safe `.archive/` moves, write approval quarantine staging, and provenance tracking (`.usage.json`).

## 2. Architecture & Core Concepts

### 2.1 Prompt Caching & Immutability
- **Static Base Prompt**: The system prompt generated by `buildUnifiedSystemPrompt()` remains immutable across turns.
- **Compact Index**: The `<skills_index>` block contains only skill names and concise 1-line summaries (maximum 60 characters).
- **On-Demand Turn**: When `skill_view` is called, the file content is returned in the normal turn stream as an Action Output.

### 2.2 Template Variables Interpolation
When loading files via `skill_view`, runtime tokens are replaced dynamically:
- `${SHARK_SKILL_DIR}`: The resolved absolute directory of the skill on disk (e.g., `/home/user/.shark/skills/my-skill`).
- `${SHARK_SESSION_ID}`: The current active conversation or task session identifier.

### 2.3 Directory Layout & Dual-Scope Resolution
Skills are searched in priority order:
1. **Local Project Scope**: `.agents/skills/<skill-name>/` (takes precedence).
2. **Global User Scope**: `~/.shark/skills/<skill-name>/`.

Structure of a skill package:
```text
<skill-name>/
├── SKILL.md                 # Mandatory instructions with YAML frontmatter
├── .usage.json              # Provenance and telemetry metadata
├── references/              # (Optional) Domain documentation, cheat sheets
│   └── api-docs.md
├── scripts/                 # (Optional) Auxiliary automation scripts
│   └── validate.sh
└── templates/               # (Optional) Scaffolding boilerplate
```

Safety directories:
- `.archive/`: Subfolder inside `.agents/skills/.archive/` and `~/.shark/skills/.archive/` where deleted skills are archived with timestamps.
- `.shark/pending/skills/<id>/`: Staging area for proposals when `skills.write_approval: true`.

## 3. Toolset & Action Specifications

Shark Dev expands its Coordinator JSON action enum (`action.type`) with three dedicated first-class actions:
`"skills_list" | "skill_view" | "skill_manage"`

### 3.1 `skills_list`
Discovers installed and active skills.

**Action Input Schema**:
```json
{
  "type": "skills_list",
  "args": {
    "query": "optional string filter"
  }
}
```

**Output**:
A formatted Markdown list:
```markdown
- **brainstorming**: Explora requisitos e design antes do código. [pinned]
- **systematic-debugging**: Depuração sistemática de bugs antes de propor correções.
- **test-driven-development**: Implementação orientada a testes com ciclo TDD. [pinned]
```

### 3.2 `skill_view`
Loads instructions or auxiliary files on demand.

**Action Input Schema**:
```json
{
  "type": "skill_view",
  "args": {
    "name": "string (required, e.g. 'brainstorming')",
    "file_path": "string (optional, relative path, default: 'SKILL.md')"
  }
}
```

**Execution Flow**:
1. Locates the skill folder in local project scope or global scope.
2. Reads the target file (defaulting to `SKILL.md` if `file_path` is omitted).
3. Strips YAML frontmatter if reading `SKILL.md`.
4. Replaces `${SHARK_SKILL_DIR}` and `${SHARK_SESSION_ID}`.
5. Updates `.usage.json` (`last_used_at`, increments `use_count`).
6. Returns the content as action output.

### 3.3 `skill_manage`
Autonomous creation, surgical patching, and maintenance of procedural knowledge.

**Supported Actions (`args.action`)**:
1. `create`: Scaffolds `<skill-name>/` directory, writes `SKILL.md`, and creates `.usage.json` (`created_by: "agent"`).
2. `edit`: Overwrites the entire `SKILL.md` content.
3. `patch`: Performs a surgical replacement of `old_string` with `new_string` in `SKILL.md`.
4. `write_file`: Creates or updates secondary files in `references/`, `scripts/`, or `templates/`.
5. `remove_file`: Deletes an auxiliary file while preserving the rest of the package.
6. `delete`: Archives the skill package by moving it to `.archive/<skill-name>_<timestamp>/`.

**Action Input Schema**:
```json
{
  "type": "skill_manage",
  "args": {
    "action": "create" | "edit" | "patch" | "write_file" | "remove_file" | "delete",
    "name": "string (required)",
    "content": "string (optional, required for create/edit/write_file)",
    "file_path": "string (optional, required for write_file/remove_file)",
    "old_string": "string (optional, required for patch)",
    "new_string": "string (optional, required for patch)",
    "scope": "local" | "global" (optional, default: "local")
  }
}
```

## 4. Governance & Safety Mechanisms

### 4.1 Pinned Skills Protection
- Skills marked in `skills.pinned` within `shark.config.json` (or `.sharkrc`):
  ```json
  {
    "skills": {
      "pinned": ["brainstorming", "systematic-debugging", "test-driven-development"],
      "write_approval": false
    }
  }
  ```
- Any `skill_manage` request with `action: "delete"` targeting a pinned skill is rejected:
  > `[Blocked]: Skill '${name}' is pinned by the user and protected against deletion.`

### 4.2 Write Approval & Staging Quarantine (`write_approval`)
- When `write_approval: true`:
  - `skill_manage` writes the request into a staging folder: `.shark/pending/skills/<id>/request.json`.
  - The agent receives:
    > `[Pending Approval]: Modification for skill '${name}' staged with ID '${id}'. Waiting for user approval via '/skills approve ${id}'.`
  - In TUI / CLI:
    - `/skills pending`: Lists pending proposals with a summary diff.
    - `/skills approve <id>`: Applies the staged change to disk.
    - `/skills reject <id>`: Deletes the staged proposal.
- When `write_approval: false`:
  - Changes are applied immediately to disk.

### 4.3 Safe Deletion via Archival
- Deleted skills are moved to `.archive/<name>_<timestamp>` instead of permanent deletion.
- Restoring an archived skill is as simple as moving the folder back.

### 4.4 Provenance & Telemetry (`.usage.json`)
Every skill package includes a lightweight `.usage.json`:
```json
{
  "created_by": "agent",
  "created_at": "2026-09-16T12:00:00.000Z",
  "last_used_at": "2026-09-16T13:00:00.000Z",
  "use_count": 1
}
```

## 5. System Prompt & Coordination Updates

### 5.1 System Prompt Changes (`prompts.ts`)
- Replace the legacy `activate_skill` guidance with the new 3-tool flow:
  ```markdown
  ⚡ CATÁLOGO DE SKILLS E MEMÓRIA PROCEDURAL (Progressive Disclosure):
  Em <skills_index> estão listados os procedimentos e metodologias disponíveis.
  1. CONSULTA DE PROCEDIMENTOS:
     - Antes de iniciar uma tarefa especializada, consulte as diretrizes detalhadas usando 'skill_view' com args: { "name": "nome_da_skill" }.
     - Se precisar de um guia ou script de apoio da skill, use 'skill_view' com args: { "name": "...", "file_path": "references/..." }.
  2. APRENDIZADO PROCEDURAL ('skill_manage'):
     - Para salvar novos fluxos de trabalho ou aprimorar diretrizes existentes, use 'skill_manage'.
     - Suporta: 'create', 'edit', 'patch', 'write_file', 'remove_file', 'delete'.
  ```
- Update `COORDINATOR_RESPONSE_JSON_SCHEMA`:
  - Add `"skills_list"`, `"skill_view"`, `"skill_manage"` to action enum.
  - Maintain `"activate_skill"` as an alias that maps internally to `skill_view` for backwards compatibility.
- Update `TOOL_ARGS_PROPERTIES`:
  - Add `file_path`, `old_string`, `new_string`, `scope`.

### 5.2 Agent Execution Loop (`developer-agent.ts`)
- Handle `skills_list`, `skill_view`, and `skill_manage` actions cleanly in the coordinator loop.
- Stop appending skill markdown to the system prompt in `stackspot-provider.ts` and `openai-compatible-provider.ts`. The system instruction remains frozen.

## 6. Verification & Test Plan

1. **Unit Tests (`skill-manager.test.ts`)**:
   - Dynamic listing (`listSkills`) with short description formatting and query filtering.
   - Reading `SKILL.md` and auxiliary files (`skill_view`) with variable interpolation (`${SHARK_SKILL_DIR}`, `${SHARK_SESSION_ID}`).
   - Template interpolation and `.usage.json` updates.
   - Pinned skills protection rejecting deletion.
   - Staging quarantine when `write_approval: true`, plus `approvePending` and `rejectPending`.
   - Surgical `patch` replacing substring without corrupting file.
   - Archiving to `.archive/` on deletion.
2. **Schema & Prompt Tests (`prompts.test.ts`)**:
   - Validate that `COORDINATOR_RESPONSE_JSON_SCHEMA` accepts `skills_list`, `skill_view`, and `skill_manage` with their respective args.
3. **Integration Tests (`developer-agent.test.ts`)**:
   - Simulate an agent execution turn where `skill_view` is called and verify that the system instruction remains static.
