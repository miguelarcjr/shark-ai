# Design Specification: subagent-driven-development-lite Improvements

**Date:** 2026-07-23  
**Status:** PROPOSED  

---

## 1. Goal & Context

When running the `subagent-driven-development-lite` workflow, the quality review step and subsequent fix cycle can fail due to two issues:
1. **Report Overwriting/Absence:** Subagents reuse static file names (like `task-N-report.md` or `task-N-review-report.md`) across multiple iterations. If a subagent fails to write the file, the next agent reads stale information or concludes there are no findings, skipping critical corrections.
2. **Terminal/Shell Commands:** Subagents attempt to run generic shell commands (such as directory creation or redirection) which fail depending on the OS shell configurations, causing the agent run to crash.

This design introduces **dynamic file naming mapped to subagent IDs**, **hybrid recovery fallback** (Dual-Write) in the orchestrator scripts, and **explicit tool-usage instructions** in prompts.

---

## 2. Proposed Changes

### 2.1. Dynamic Naming Schema

Every report generated by a subagent must have a unique filename containing the subagent's execution ID:

* **Implementer / Fixer Report:**  
  `task-subagent-[SUBAGENT_ID]-report.md`
* **Reviewer Report:**  
  `task-subagent-[SUBAGENT_ID]-review-report.md`

#### Handoff Resolution Logic:
* When preparing the Quality Review step, the script `prepare-brief.mjs reviewer` parses `.shark/subagents.json`, identifies the ID of the last completed `Implementer` or `Fixer` subagent for the current task, and injects that path as the `[REPORT_FILE]` placeholder.
* When preparing the Fix step, the script `prepare-brief.mjs fix` parses `.shark/subagents.json`, identifies the ID of the last completed `Reviewer` subagent, and injects that path as the `[REVIEW_REPORT_FILE]` placeholder.

---

### 2.2. Hybrid Recovery (Fallback) in `prepare-brief.mjs`

To ensure the physical files are always present on disk for the next agent:

* **Implementer Report Check (Reviewer Setup):**
  If `task-subagent-[IMPLEMENTER_ID]-report.md` does not exist on disk, the script parses `.shark/subagents.json`, retrieves the content of the `complete_task` call from `subagents[IMPLEMENTER_ID].lastAction.params.content`, and writes it to disk.
* **Reviewer Report Check (Fixer Setup):**
  If `task-subagent-[REVIEWER_ID]-review-report.md` does not exist on disk, the script parses `.shark/subagents.json`, retrieves `subagents[REVIEWER_ID].lastAction.params.content` (which holds the full markdown findings), and writes it to disk before launching the Fixer.

---

### 2.3. Prompt Template Enhancements

#### `task-reviewer-prompt.md`
* Include a strict requirement section explaining that the agent **must** call the file-writing tool (e.g. `write_to_file`) with the `TargetFile` parameter set exactly to `[REVIEW_REPORT_FILE]` to dump the full report, and only then call `complete_task` with the summary.
* Provide an explicit example showing how to invoke the file writing tool:
  * E.g. call `write_to_file` with `TargetFile: "[REVIEW_REPORT_FILE]"` and `CodeContent` containing the markdown review.
* Strictly forbid using shell commands (like `mkdir`, `echo`, `cat`, etc.) to create folders or files. Directories are pre-created by the script; files must be created via standard tools.

#### `implementer-prompt.md`
* Include a similar requirement section for writing the implementation report to `[REPORT_FILE]`.
* Provide an explicit example showing how to invoke the file writing tool to create the report.
* Instruct the subagent not to run shell commands to create or populate files.

---

## 3. Verification Plan

1. **Unit Test for Recovery:** Run the briefing script with a missing report file on disk to verify that `prepare-brief.mjs` automatically reconstructs it using the JSON history.
2. **Dry Run:** Manually execute the `prepare-brief.mjs` modes to verify that files are successfully written with subagent IDs in their names.
